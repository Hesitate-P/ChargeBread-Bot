# 🍞 充能面包 bot

QQ 群聊娱乐机器人。用户发 `/充能面包` 签到领面包，看排行榜，攒连签。

```
# 🍞 充能完成

**Hesitate_P** 今天第 🥉 **3** 个签到

- 获得 **16** 个面包 🍞
- 连签 **5** 天 · 加成 +25%
- 累计 **142** 个面包 · 今天已有 **17** 人签到

![充能面包 #160px #160px](https://…/ChargeBread.png)
```

## 快速开始

### 本地跑（开发用）

```bash
cp .env.example .env      # 填 QBOT_APP_ID / QBOT_APP_SECRET / BREAD_IMAGE_URL
python3 -m chargebread
```

看到这两行就是成功了：

```
INFO chargebread.gateway: 已连接网关（第 1 次），intents=117440512
INFO chargebread.gateway: READY session_id=… 机器人=充能面包bot
```

然后把机器人拉进群，`@` 它一下。

### Docker 部署

```bash
docker compose up -d
docker compose logs -f
```

**不需要**端口映射、域名、证书或 ICP 备案——事件走 WebSocket 出站长连接。

> ⚠️ 容器里 `TZ=Asia/Shanghai` 和 `PYTHONUNBUFFERED=1` 是必需的，compose 与
> Dockerfile 都已设置。少了前者，签到的"每日 0 点重置"会发生在北京时间早上 8 点；
> 少了后者，`docker logs` 看不到实时日志。

## 命令

| 命令 | 作用 |
|---|---|
| `/充能面包` | 今日签到。也认 `充能面包`（不带斜杠）、全角斜杠 `／` |
| `/面包排行榜 [本群\|全部]` | 面包总数榜，默认本群 |
| `/签到排行榜 [本群\|全部]` | 今日签到顺序榜，默认本群 |
| `/我的面包` | 个人详情：累计、今日排名、连签、历史最高、补签卡 |
| `/补签` | 用补签卡补回昨天，把连签接上 |
| 空 `@` 或 `/帮助` | 菜单 |

参数是**宽进**的：`全部`/`全服`/`所有`/`all` 都认，`本群`/`群内`/`group` 都认，
打错字**静默回落本群**——不因为一个错别字把人挡在门外。
命令和参数之间漏空格也认（`面包排行榜全部`）。

排行榜和签到回复上都挂了按钮：切「本群/全部」、切「面包/签到」、刷新、补签、看个人页。

## 玩法规则

数值全部集中在 [`chargebread/rules.py`](chargebread/rules.py)，改平衡不用碰业务逻辑。

- **面包** = 基础 10 × 排名系数 × 随机浮动(0.9~1.1) × 连签加成
- **排名系数**：第 1 名 ×1.5 / 第 2 名 ×1.35 / 第 3 名 ×1.25 / 4~10 名 ×1.1 / 11 名起 ×1.0
- **连签加成**：**签到第 1 天就算 +5%**，之后每天再 +5%，10 天封顶 +50%；**断签清零**
- **补签卡**：连签每满 7 天送 1 张；只能补**昨天**；补签发保底 9 个面包、**不计排名**、续上连签
- **全局一天只能签一次**：不管你在几个群里，今天签过就不能再签

最后一条是硬保证，落在数据库的唯一约束上（`UNIQUE(signin_date, user_id)`），
所以连点两次按钮、或平台重复推送事件，都不会多出一次签到。

## 已实测的平台行为

这些都是**真实调用验证过**的，不是照文档抄的。文档有几处与事实不符，
记在这里免得以后有人再踩：

| 事项 | 实测结论 |
|---|---|
| 群聊 intents | **无需申请**，`1<<24/1<<25/1<<26` 全部可连（文档说"特殊事件需申请"） |
| 网关地址 | `GET /gateway` 返回 **`wss://api.sgroup.qq.com/websocket`**，不是文档写的统一域名 |
| 昵称 | 群消息事件里 **`author.username` 有真实值**，不需要任何申请 |
| 跨群身份 | **`author.id` 跨群一致**（双人双群交叉验证），所以"全部榜"和"全局一天一签"可行 |
| 头像 | **拿不到**。群聊没有任何头像接口，机器人自己的头像也是不可推导的签名 URL |
| 成员信息接口 | `11253 应用无接口访问权限`，白名单内邀制。但昵称已从事件拿到，不需要它 |
| 群基本信息 | `GET /v2/groups/{g}/info` **可用**（文档挂了白名单横幅，实际不拦） |
| markdown 内嵌图 | **可用，不需要域名报备**，非 443 端口也放行 |
| 按钮 | 可用。回调 `type=11`，**必须 3 秒内 `PUT /interactions/{id}` 应答** |
| 两个 id 不一样 | 应答用 `d.id`，被动回复的 `event_id` 用**外层信封 id**（`INTERACTION_CREATE:uuid`）。混用报 `40034025` |
| 消息内容 | `content` **前后带空格**（@ 前缀被平台剥掉但空格留着），必须 `strip()` |
| 主动推送 | 群里默认**关闭**（`allow_proactive_msg: false`），管理员可开。本 bot 纯被动回复，不受影响 |
| IP 白名单 | **不是上线前提**。「未设置时所有请求来源 IP 都会被允许调用」（文档原文）。设了则只放行单个 IPv4，不支持 CIDR，最多 50 条 |

> 上表每一条都是真机验证或文档原文逐字核对过的。**不要**把未经核对的转述写进这里——
> 本项目就发生过一次：一条"新增机器人必须填写 IP 白名单才能提审上线"的说法被写进
> 文档，实际平台上根本不存在这句话，而它会把动态 IP 家用部署的结论引向完全相反的方向。

## 运维须知

- **IP 白名单不是上线前提。** 文档原文：「未设置 IP 白名单时，所有请求来源 IP 都会被
  允许调用，建议至少添加一条以提升安全性。」
  设置后**仅**白名单内的地址可调用，只支持单个 IPv4、不支持 CIDR 网段、最多 50 条。
  所以：**家用动态 IP 就别设**（设了反而会把自己挡在门外）；只有在机房/固定 IP
  部署、想收紧调用来源时才建议设置。
- **主动推送不做**：本 bot 所有交互都由用户动作触发，不依赖主动消息。
  实测 `bot_state.allow_proactive_msg` 在群里默认为 `false`，群管理员可开。
- 数据库是唯一需要备份的东西：`data/chargebread.sqlite3`（WAL 模式，连带 `-wal`/`-shm`）。

## 开发

```bash
python3 -m unittest discover -s tests -v     # 205 个测试
python3 probe/probe.py --intents-only        # 探测平台能力（需 .env 里有凭据）
python3 probe/check_url.py <图片URL>          # 上线前验证图片可达性
```

代码按职责分层，每层都能单独测：

```
config.py     配置（凭据只从 .env 读，代码里无字面量）
rules.py      玩法数值与公式
db.py         SQLite 存储，唯一约束兜底
game.py       签到/补签/连签领域逻辑
render.py     markdown 排版与按钮
commands.py   命令与参数解析（按钮回调和文本走同一个解析器）
api.py        HTTP 客户端：token 后台续期、只重试网络错、3 秒应答单次机会
gateway.py    WS 长连接：握手、心跳、退避重连、事件分发
bot.py        接线：把事件翻译成动作
netguard.py   出站 URL 守卫（SSRF 防护）
```

### 两条写法约定（工具链强制）

1. **SQL 必须与 `execute(` 同一行，且不能把变量当首参。** 项目安全扫描按行匹配，
   SQL 换行会被判为"拼接构造"，传模块常量会被判为"用户输入拼接"。值一律走 `?`。
2. **出站 URL 一律先过 `netguard`**，只允许 http/https(/ws/wss)、拒绝内网与回环地址。
